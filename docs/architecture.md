# Архитектура клиента

## Слои

```
┌───────────────────────────────────────────────┐
│ UI (минимум): connect, выбор канала, статус    │
├───────────────────────────────────────────────┤
│ Подписка: загрузка subscription.txt,           │
│           парсинг vless:// → модель канала     │
├───────────────────────────────────────────────┤
│ Генерация конфига ядра (Xray-core JSON)        │
├───────────────────────────────────────────────┤
│ Ядро Xray-core: VLESS + REALITY (xhttp/vision) │
├───────────────────────────────────────────────┤
│ Системный туннель:                             │
│   Android: VpnService tun → tun2socks → SOCKS  │
│   Windows: WinTun     tun → tun2socks → SOCKS  │
└───────────────────────────────────────────────┘
```

Ядро поднимает локальный **SOCKS-инбаунд** на `127.0.0.1`; `tun2socks`
заворачивает в него системный трафик из tun-интерфейса. Такой же приём
используют зрелые клиенты — мы лишь не берём их GPL-код.

## Поток данных

1. Пользователь получает у администратора **персональную** подписку
   (`clients/<имя>/subscription.txt`) — это ссылка/файл с двумя `vless://`.
2. Приложение один раз импортирует подписку (вставить текст / отсканировать QR)
   и сохраняет её локально.
3. При подключении приложение:
   - строит конфиг Xray-core для выбранного канала (xHTTP по умолчанию, Vision —
     как резерв);
   - поднимает SOCKS-инбаунд и `tun2socks`;
   - просит у ОС разрешение на VPN (Android: диалог `VpnService`; Windows:
     UAC-запуск).
4. Трафик идёт в tun → tun2socks → SOCKS Xray → сервер.

## Модель канала (общий контракт)

Из `vless://` извлекаются: `uuid`, `host`, `port`, `sni`, `pbk`, `sid`, `fp`,
`type` (`xhttp`|`tcp`), `path`, `mode`, `flow`. Схема и фикстуры —
в [`shared/`](../shared/README.md). Оба клиента обязаны давать одинаковый
результат на одних и тех же ссылках — это проверяется одними фикстурами.

## Безопасность

- **Подписка = секрет.** В ней UUID пользователя (пароль доступа). Хранится
  локально в приватном хранилище приложения; в логах не печатается; в
  репозиторий не коммитится.
- На сервере ключи REALITY и UUID живут только в `/etc/vpn-server` и `clients/`.
- Клиент не хранит приватных ключей сервера — ему нужны только публичные
  параметры REALITY (`pbk`, `sid`, `sni`).

## Обновления

- **Подписка:** приложение периодически перечитывает свой `subscription.txt` —
  если администратор сменил SNI/ключи, ссылку нужно обновить вручную (клиент
  покажет, что профиль устарел).
- **Приложение:** проверяет свежий релиз на GitHub Releases и предлагает
  обновиться (магазины не задействованы).
